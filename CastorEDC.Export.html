    CastorEDC.Export (ExCastorEDC v1.0.0-rc.1)

    Copy Markdown View Source

    Batch exports: a study's data, structure, queries and more, as files.

    The API runs an export as a background job. You queue it, wait until it's ready, and download the result, which is always a zip. This module does each of those steps on top of CastorEDC.Exports.

    There's a function for each type of export that does all three, such as participant_data/3:

    {:ok, %CastorEDC.Export{path: path}} =
  CastorEDC.Export.participant_data(client, study_id,
    format: :spss,
    filters: [site_ids: [site_id]],
    options: [include_comments: true],
    into: "exports/"
  )

    The steps are functions too, for queuing several exports at once or picking up later: queue/4 queues exports, await/4 waits until they're ready, status/3 looks one up, and download/4 downloads a ready one.

    Waiting

    The API has no way to wait for an export, so await/4 polls the export list: after 1 second, then each time half as long again, up to every 15 seconds. One poll covers every export being waited for. The polls go through CastorEDC.Client like any other request, so they count against the rate limit and appear in its telemetry.

    Telemetry

    • [:castor_edc, :export, :queued] - with the number of exports as :count, and the :study_id, :export_ids and :types as metadata
    • [:castor_edc, :export, :poll] - each time await/4 checks, with the number of exports still running as :pending, and the :study_id and :export_ids as metadata
    • [:castor_edc, :export, :completed] and [:castor_edc, :export, :failed] - for each export await/4 sees finish, with the time it waited as :duration (in native time units), and the :study_id and :export as metadata
    • [:castor_edc, :export, :timeout] - when await/4 gives up, with :duration, and the :study_id and :export_ids as metadata

    Concurrent exports

    The API runs at most three exports per user at a time, and refuses to queue more. With rate_limit: :wait (the default of CastorEDC.new/1), queue/4 waits for a slot, trying again after 5 seconds, then 10, 20, 40 and every 60, for as long as its :timeout allows. With rate_limit: :error, or once the time is up, it returns an error with code :too_many_exports.

    The struct

    • :id - the export's ID
    • :type - the export type, such as :participant_data
    • :format - the file format, such as :csv
    • :status - :queued, :in_progress, :ready or :failed
    • :file_name and :file_size - the file, once the export is ready
    • :created_by - the ID of the user who queued the export
    • :created_on, :completed_on and :expires_on - when the export was queued, finished and stops being available (7 days later)
    • :data - the downloaded file, when download/4 kept it in memory
    • :path - where download/4 saved the file, when given :into; with unzip: true, the directory the files went into
    • :files - with unzip: true, the files in the zip: their paths, or {name, contents} tuples when the export was kept in memory

    Types, formats and statuses the client doesn't know stay strings.

    await(client, study_id, export_ids, opts \\ [])

    @spec await(CastorEDC.client(), String.t(), [String.t()], keyword()) ::
  {:ok, [t()]} | {:error, CastorEDC.Error.t()}

    Waits until every export in export_ids is ready, and returns them in the same order.

    It doesn't download them: see download/4. When an export fails, it returns an error with code :export_failed and the export in result straight away. An ID that doesn't show up in the export list within 30 seconds returns an error with code :export_not_found.

    Options

    • :timeout - how long to wait, in milliseconds or :infinity; 15 minutes by default. Then it returns an error with code :export_timeout, with the IDs of the exports that weren't ready in export_ids. They keep running, so you can call await/4 with those IDs again.
    • :poll_interval - the first wait before checking, in milliseconds; 1 second by default
    • :since - a DateTime from before the exports were queued, which lets each check stop paging through the export list at older exports

    download(client, study_id, export, opts \\ [])

    @spec download(CastorEDC.client(), String.t(), t(), keyword()) ::
  {:ok, t()} | {:error, CastorEDC.Error.t()}

    Downloads a ready export.

    Every export downloads as a zip. Without :into, the file comes back in memory, in the struct's :data.

    Options

    • :into - save the file instead, streaming it to disk so it never sits in memory as a whole. An existing directory, or a path ending in /, saves it there under the export's file name; any other path is the file to write. Missing directories are created. The struct's :path says where the file went.

    Any other option is passed to Req.

    An export that isn't ready returns an error with code :export_not_ready, and one past its expiry date an error with code :export_expired.

    queue(client, study_id, requests, opts \\ [])

    @spec queue(CastorEDC.client(), String.t(), [{type(), keyword()}], keyword()) ::
  {:ok, [String.t()]} | {:error, CastorEDC.Error.t()}

    Queues exports, returning their IDs in the order of requests.

    requests is a list of {type, opts} tuples, all sent in one request:

    {:ok, [data_id, sites_id]} =
  CastorEDC.Export.queue(client, study_id, [
    {:participant_data, format: :spss, filters: [site_ids: [site_id]]},
    {:sites, []}
  ])

    Each export takes these options:

    • :format - one of the type's formats, by default its first
    • :filters and :options - keyword lists of the type's filters and options. Values are given as Elixir values: lists, booleans, integers, Dates (and NaiveDateTimes where the API takes a time too), and atoms for values from a fixed set, such as display_options_as: :names or element_type: :visit.

    A type, format, filter or option the API doesn't support, or a value of the wrong kind, raises ArgumentError.

    Options

    • :timeout - how long to wait for a free slot when three exports are already running (see Concurrent exports), in milliseconds or :infinity; 15 minutes by default

    status(client, study_id, export_id)

    @spec status(CastorEDC.client(), String.t(), String.t()) ::
  {:ok, t()} | {:error, CastorEDC.Error.t()}

    The current state of an export.

    There's no endpoint for a single export, so this pages through the study's export list, newest first, until it finds export_id. An ID that isn't in the list returns an error with code :export_not_found. That includes an export queued a moment ago: it takes the API a few hundred milliseconds to list it.

    • :form_collection_types (a list of strings)
    • :participant_id (a list of strings)
    • :sites (a list of strings)
    • :triggered_after (a Date)
    • :triggered_before (a Date)
    • :validation_statuses (a list of strings)
    • :validation_types (a list of strings)

    Options: none.

    Options

    • :format, :filters and :options - as above
    • :into - a directory, or a file path, to stream the zip to, as for download/4
    • :unzip - when true, unzips the export: into the :into directory (a file path given as :into becomes a directory of that name), or in memory. The struct's :files lists what was in it.
    • :timeout - how long to wait for the export, queuing included, in milliseconds or :infinity; 15 minutes by default
    • :poll_interval - the first wait before checking on the export, see await/4

    Any other option is passed to Req for the download. A format, filter or option the export doesn't take raises ArgumentError before anything is sent.
